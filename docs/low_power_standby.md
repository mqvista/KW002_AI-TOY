# KW002 功放门控与定时休眠

## 默认行为

- `xiaozhi_toy` 启动时将 P19 设为低电平。音频驱动注册使用无 PA 引脚的配置，播放线程独占实际 P19 控制；`hw_test` 保留原有行为。
- 提示音、激活码和 WebSocket 回答共用播放线程。首帧写入前开启功放并等待 20 ms；根据成功写入的 PCM 时长估算底层缓冲播放结束，再保留 200 ms 后关闭。
- 间隔较短的语句共用一次功放开启。音量 0 时保持功放关闭，保存的用户音量不因待机改变。
- 只有进入就绪后的 idle/offline 状态才检查定时休眠。播放、对话、充电、按键按住都会重新开始完整的 5 分钟计时；配网、激活和启动联网不触发自动休眠。
- 进入休眠前关闭会话，停止采音和 KWS，等待播放线程确认暂停后关闭音频，再关闭 Wi-Fi。休眠前再次检查按键、充电状态与活动序号。
- 按键/KWS 回调在投递事件前更新活动序号，准备阶段收到的新操作可取消尚未提交的休眠。
- 准备失败会恢复音频与待机状态；Wi-Fi 已关时通过 offline 流程重连。音频恢复失败则重启。失败尝试至少间隔 60 s。
- P33 是深睡唤醒源。唤醒后从启动流程重新初始化并联网，播放就绪提示后恢复待机；唤醒这一按仅用于启动，就绪后可说“小智同学”或再按 P33 对话。

## 可调参数

均在 `apps/xiaozhi_toy/src/xz_config.h`：

| 参数 | 默认 | 含义 |
|---|---|---|
| `XZ_PA_START_MS` | 20 ms | PA 开启稳定时间 |
| `XZ_PA_TAIL_MS` | 200 ms | PCM 预计播放结束后的保持时间 |
| `XZ_IDLE_SLEEP_MS` | 300000 ms | 空闲休眠间隔；0 禁用自动休眠 |
| `XZ_SLEEP_RETRY_MS` | 60000 ms | 失败尝试的最小间隔 |

## 平台边界

- 深睡关闭采音与 KWS，不支持语音唤醒，也不保留网络连接。
- T5 SDK 的深睡入口会将参数写到 Flash，重启后才进入深睡。提交 SDK 深睡调用以后，按键行为应按该重启/唤醒过程测试，不能视为可撤销的普通函数。
- `0x7dc000` 到 `0x7dcfff` 是 SDK 深睡参数扇区，位于其用户资源区末尾，应保留给休眠参数。每次进入流程会擦写该扇区，需避免把休眠间隔设得很短后长期运行。
- 早期深睡回调只处理 P19 关闭、P8 熄灭和 P33 上拉，不依赖应用的队列、定时器或 PWM。
- `P21=低` 只表示正在充电，没有独立的 USB 插入或充满检测信号。充满仍插线时可能开始空闲计时；插入充电线唤醒不在本次实现范围内。
- 播放结束时间是基于成功提交的 PCM 时长估算，不是 DAC 硬件完成中断；200 ms 余量需由真机尾音测试确认。

## 真机验收

1. 冷启动及待机测量 P19 为低；每一种提示音、激活码、服务器回答均能开启 PA，播放完自动关闭。检查第一音节、尾音和开关爆音。
2. 连续短句、长回答、语音插话、P33 打断、音量 0/恢复，均无异常；断网后提示音也能正常播放并关闭 PA。
3. 空闲约 5 分钟进入深睡；对话和播放期间不睡。按住 P33/P12、充电时不睡，解除条件后重新计时。
4. 准备休眠时按键或接入充电器，检查取消/恢复；同时测试 SDK 提交后的重启窗口。
5. P33 唤醒后联网、唤醒词和再次对话正常。至少重复 100 次休眠/唤醒，确认音量、Wi-Fi 凭据与 UUID 不丢失。
6. 从电池端记录原待机、PA 关闭后待机及深睡电流，排除 USB-TTL 反向供电。功耗和续航数据以测量为准。

调试时可暂时缩短休眠时间，正式验收后恢复 300000 ms。串口请使用 `tools/monitor.py`，保持 RTS/DTR 释放。
